# TickOff Clone

A habit tracker inspired by **TickOff** (streak visualization, list view, journal
with photos, backdating, light/dark themes) built with **Flutter** + **Supabase**,
plus a native **Android home-screen widget** for ticking habits without opening
the app. A web app can reuse the same Supabase backend as a separate project later.

```
tickoff_clone/
├── supabase/
│   └── schema.sql          # run this once in your Supabase project
└── flutter_app/            # the Flutter app + Android widget
```

## 1. Set up Supabase

1. Create a project at https://supabase.com.
2. Open **SQL Editor** → paste the contents of `supabase/schema.sql` → **Run**.
   This creates all tables, row-level security policies, the private
   `journal-media` storage bucket, and a settings-on-signup trigger.
3. Go to **Project Settings → API** and copy:
   - **Project URL**
   - **anon public key**
4. (Optional) In **Authentication → Providers**, email/password is enabled by
   default — that's all this app uses. Turn off "Confirm email" while
   developing if you don't want to click a confirmation link every time you
   test signup.

## 2. Configure the Flutter app

The app reads your Supabase credentials from `--dart-define` flags rather
than a hardcoded file, so you never commit real keys.

```bash
cd flutter_app
flutter pub get
```

**First-time Android build note:** this project's `android/` folder was
hand-assembled rather than generated by `flutter create`, so the Gradle
wrapper *scripts* (`gradlew`, `gradlew.bat`) and the wrapper jar aren't
included — only `gradle/wrapper/gradle-wrapper.properties` (pinned to Gradle
8.14) is. Before your first build, run once from `flutter_app/`:

```bash
flutter create --platforms=android .
```

This is safe and non-destructive — it only fills in missing platform
scaffolding (the wrapper jar/scripts) and won't touch your `lib/`,
`pubspec.yaml`, or the widget files already in `android/app/`.

Build tool versions in this project (`android/build.gradle`,
`android/settings.gradle`, `android/app/build.gradle`) are pinned to
versions verified to work together as of this writing:
- Gradle 8.14
- Android Gradle Plugin (AGP) 8.11.1
- Kotlin 2.2.20
- `compileSdk` 36 (required by some plugin AARs' metadata even though
  `targetSdk` stays at 34)

If `flutter doctor` or a build error asks for newer versions (e.g. AGP 9.x),
you can usually ignore the "support will soon be dropped" warning for now —
AGP 9 changes the Gradle DSL and would need further edits to this project's
`build.gradle` files.

You'll also need a JDK 17 (not whatever ships with newer Android Studio
versions) — set it once via:

```bash
flutter config --jdk-dir=/path/to/your/jdk-17
```

Run the app with:

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=YOUR-ANON-KEY
```

Tip: save that command in a `run.sh` (gitignored) so you don't retype it, or
configure it as a "Custom Run Configuration" in Android Studio / VS Code
under `--dart-define`/`args`.

## 3. Try it out

- Sign up with an email/password (check Supabase Auth logs if you don't get
  a confirmation email in dev).
- Tap **New habit**, pick an icon/color, set daily or weekly frequency.
- Tap the circle on a habit to tick it off; tap the row to open details,
  where you can tap any past day on the calendar to backdate a tick.
- Add a **Journal** entry with a note and/or photo, optionally linked to a
  habit — photos upload to the private `journal-media` bucket and are shown
  via short-lived signed URLs.
- Open a habit's detail screen to see its **streak heatmap** (a GitHub-style
  contribution grid, colored in the habit's own color) alongside current/best
  streak stats and the backdating calendar.
- Set a **reminder time** when creating/editing a habit to get a daily local
  notification at that time — see section 5 below.
- In **Settings**, switch your default home view between Streak View and
  List View, matching TickOff's "two home screens" feature.

## 4. Try the widget and reminders

See sections 5 and 6 below for the full setup steps for reminder
notifications and the Android home-screen widget.

Each habit can have an optional `reminderTime`. When set (or changed), the
app schedules a **daily repeating local notification** at that time via
`flutter_local_notifications`:

- On first launch, Android 13+ will prompt for notification permission
  (`POST_NOTIFICATIONS`) and, if needed, exact-alarm permission — this
  happens automatically via `NotificationService.init()` in `main.dart`.
- Creating/editing a habit with a reminder time calls
  `NotificationService.scheduleForHabit`, which cancels any existing
  reminder for that habit and schedules a new one using
  `matchDateTimeComponents: DateTimeComponents.time` so it repeats daily
  without you needing a background task.
- Archiving or deleting a habit cancels its reminder.
- On every app launch, `resyncAll()` re-schedules every active habit's
  reminder as a safety net (handles edge cases like the OS clearing alarms).

**Testing tip:** set a reminder time a minute or two in the future, then
background the app (don't force-close it) and wait — you should see the
notification even with the screen off. If nothing arrives, check that
notification permission was actually granted in Android's app settings, and
that battery optimization isn't restricting the app (some OEMs, e.g.
Xiaomi/Huawei, are aggressive about killing background alarms).

## 6. Add the Android home-screen widget

1. Build and install the app on a device/emulator (`flutter run` or
   `flutter build apk` + install) and log in at least once so it has habits
   to show.
2. Long-press an empty spot on the Android home screen → **Widgets** →
   scroll to **TickOff Clone** → drag the widget onto the home screen.
3. The widget shows today's habits with their streak length. Tapping a
   habit's circle ticks it off immediately — this works via a background
   broadcast (`home_widget` package) straight into `HabitService`, so the
   app doesn't need to be open.
4. The app also pushes a fresh snapshot to the widget any time you tick a
   habit from inside the app itself, and Android auto-refreshes it roughly
   every 30 minutes as a fallback (`updatePeriodMillis` in
   `habit_widget_info.xml`).

### How the widget works, in short

- `lib/services/widget_service.dart` serializes today's habits (id, name,
  color, done-today, streak) to JSON and hands it to the `home_widget`
  plugin, which stores it in Android `SharedPreferences`.
- `HabitWidgetProvider.kt` is the `AppWidgetProvider` that lays out the
  widget shell and points its `ListView` at a `RemoteViewsService`.
- `HabitWidgetService.kt` reads that same JSON and renders one row per
  habit, wiring each row's tap to a fill-in intent that ultimately invokes
  `backgroundCallback()` back in Dart (see `widget_service.dart`), which
  ticks the habit in Supabase and re-syncs the widget.

## 9. Bug fixes: tick mark & widget sync

Two real bugs were fixed (not workarounds):

1. **"Tick mark only updates after a manual refresh"** — `HabitsNotifier.tick()`
   / `.untick()` updated the database and the widget, but never invalidated
   `weekLogsProvider`, which is what actually drives the "done today" circle
   and streak count on the Streak/List views. Pull-to-refresh happened to
   invalidate it manually, which is why refreshing "fixed" it. Fixed by
   invalidating `weekLogsProvider` (and `habitLogsProvider`) right after
   every tick/untick.

2. **"Widget data isn't in sync with the app"** — had two causes:
   - The widget's background tap handler (`backgroundCallback` in
     `widget_service.dart`) runs in a fresh background isolate spawned by
     Android, which does **not** share memory with your running app —
     Supabase was never initialized there, so tapping a habit in the widget
     silently failed to write anything to the database. Fixed by calling
     `Supabase.initialize()` inside that callback (it recovers the same
     signed-in session from local storage, no re-login needed).
   - Even once that write succeeds, the app's in-memory Riverpod state
     doesn't know about it until something tells it to refetch. Fixed by
     adding a `WidgetsBindingObserver` to `HomeScreen` that invalidates
     `habitsProvider`, `weekLogsProvider`, and `journalEntriesProvider`
     whenever the app is resumed from the background — so reopening the app
     after ticking something from the widget shows the latest state
     immediately, no manual pull-to-refresh needed.

## 10. What's not included / next steps

- **iOS widget**: you asked for Android only, so no WidgetKit extension is
  included. If you want it later, `home_widget` supports iOS too, but it
  needs an Xcode-side Widget Extension target that can't be generated from
  here — happy to add the Dart-side plumbing when you're ready to build it
  in Xcode.
- **Web app**: this repo intentionally only covers mobile — build the web
  app as a separate project against the same Supabase instance whenever
  you're ready; the schema and RLS policies already support it as-is.
- **App icons**: uses Flutter's default `ic_launcher` mipmap placeholders —
  swap in your own via `flutter_launcher_icons` before publishing.
